01
Visão Geral do Projeto
O que é, para que serve e como está estruturado

CodeRyse Academy é uma plataforma de ensino online desenvolvida como protótipo funcional para o PIM3 (Projeto Integrado Multidisciplinar) do curso de Análise e Desenvolvimento de Sistemas da UNIP. Simula um ambiente completo de gestão acadêmica com quatro perfis de acesso distintos.

🎓
Aluno
Acessa cursos, conteúdos, quizzes, progresso e certificados
👨‍🏫
Professor
Cria avaliações, conteúdos, gerencia turmas e alunos
📋
Coordenador
Supervisiona cursos, módulos, turmas e matrículas
🔐
Admin
Controle total: usuários, cursos, matrículas, catálogo

Tipo de Aplicação

O projeto é uma SPA (Single Page Application) — ou seja, o navegador carrega uma única página HTML e toda a navegação acontece via JavaScript, sem recarregar a página. O Vite compila os arquivos JSX/CSS em módulos JavaScript que o navegador entende nativamente.

Arquivos Raiz — Configuração
Os três arquivos na raiz do projeto que definem como tudo funciona
📄 package.json
Manifesto do projeto Node.js. Define nome, versão, scripts de terminal e todas as dependências instaladas via npm.

Scripts disponíveis no terminal

ComandoO que faz
npm run devInicia o servidor de desenvolvimento na porta 5173 com hot reload (atualiza o navegador automaticamente ao salvar)

⚙️ vite.config.js
Arquivo de configuração central do Vite. Define plugins, aliases de importação e porta do servidor.

Configurações importantes

  • Alias @: qualquer import com @/ aponta para a pasta src/. Exemplo: import Modal from "@/componentes/Modal.jsx" em vez de ../../componentes/Modal.jsx"
  • Plugin React: habilita o suporte a JSX (sintaxe HTML dentro do JavaScript)
  • Plugin HTML: lê o arquivo src/impressao/versao-impressao.html e injeta dentro do index.html no build
  • Porta fixa: servidor sempre sobe na porta 5173
🌐 index.html
O único arquivo HTML real da aplicação. Serve como casca — o React preenche o conteúdo dinamicamente via JavaScript.

O que contém

  • Meta tags de SEO: título, descrição, viewport
  • Open Graph (og:title, og:description) para compartilhamento em redes sociais
  • Link para Google Fonts (Inter)
  • <div id="raiz"></div> — ponto de montagem do React
  • <script type="module" src="/src/principal.jsx"> — carrega a aplicação
  • Bloco #versao-impressao injetado pelo vite-plugin-html (visível apenas ao imprimir)
03
Como o Vite Serve a Aplicação
O caminho desde o npm run dev até o navegador exibir a tela
1
npm run dev — inicia o Vite Dev Server na porta 5173. O Vite não empacota os arquivos, serve cada módulo individualmente via HTTP/2 de forma nativa (ES Modules nativos do navegador).
↓
2
index.html — o navegador recebe o HTML. Encontra o <script type="module"> apontando para /src/principal.jsx.
↓
3
principal.jsx — o Vite transforma o JSX em JavaScript puro em tempo real (via esbuild, compilador ultraveloz). Importa todos os arquivos CSS e chama inicializar() do db.js.
↓
4
db.js — verifica se o localStorage já tem dados (cdr_seed_v2). Se não, popula com todos os dados do dadosMock.js. Cada visita posterior lê do localStorage.
↓
5
React monta — createRoot(document.getElementById("raiz")).render() substitui a div vazia pelo componente <Aplicacao /> dentro de um <BrowserRouter>.
↓
6
Aplicacao.jsx — verifica localStorage em busca de coderyse-perfil. Se existe, mantém usuário logado e renderiza o painel. Se não, mostra as rotas públicas.
↓
7
Hot Module Replacement (HMR) — ao salvar qualquer arquivo .jsx ou .css durante o desenvolvimento, o Vite atualiza somente o módulo alterado no navegador sem recarregar a página, preservando o estado.
Por que o Vite é rápido? Diferente do Webpack (que empacota tudo antes de servir), o Vite usa os ES Modules nativos do navegador moderno. Cada arquivo é servido individualmente sob demanda. O servidor inicia em menos de 1 segundo mesmo em projetos grandes.

db.js — Persistência com localStorage

Camada de abstração que usa o localStorage do navegador como banco de dados. Todas as mudanças feitas na plataforma (criar curso, aprovar matrícula, marcar conteúdo como concluído) são salvas aqui e sobrevivem ao fechar/abrir o navegador.

Funções exportadas

  • inicializar() — chamada no startup. Se cdr_seed_v2 não existe, popula tudo. Se existe, garante que questões padrão estejam atualizadas.
  • resetar() — remove todas as chaves cdr_*. Na próxima visita, inicializar() popula tudo novamente do zero.
  • db.cursos.listar() / db.cursos.salvar(lista) — lê/escreve cursos
  • db.usuarios.salvarPorTipo(tipo, lista) — atualiza apenas usuários de um tipo (ex: "Aluno"), preservando os demais
  • db.progresso.listarConcluidos() — retorna um Set com IDs de conteúdos concluídos
  • db.progresso.listarResultados() — retorna objeto com resultados de quizzes
Por que localStorage e não um banco de dados real? O projeto é um protótipo frontend-only. O localStorage simula a persistência que um banco de dados real (MySQL, PostgreSQL) faria — mas sem servidor. Ao "resetar", é como "dropar e recriar" o banco.

permissoes.js — Controle de Acesso (RBAC)

Implementa o padrão RBAC (Role-Based Access Control) — cada perfil de usuário tem um conjunto definido de seções visíveis e ações permitidas.

Como funciona na prática

  • A BarraLateral chama obterSecoesPermitidas(usuario.tipo) para saber quais itens renderizar no menu
  • Cada tela chama podeCriar(), podeEditar(), podeExcluir() para mostrar ou esconder botões de ação
  • eGestor() retorna true para Admin e Coordenador — usado para liberar visões gerenciais

Pasta src/paginas/
Todas as telas da aplicação organizadas por contexto

Cada arquivo dentro de paginas/ é um componente de tela — renderiza uma página completa. O arquivo LayoutWorkspace.jsx é a casca que contém sidebar, topbar e renderiza a tela correta conforme a URL.

📄 LayoutWorkspace.jsx
O "esqueleto" do painel autenticado. Fica sempre visível após o login e muda apenas o conteúdo central conforme a seção ativa.
  • Estado compartilhado Mantém em memória: conteúdos concluídos, quizzes aprovados, resultados de avaliações, favoritos, lista de cursos e toasts. Passa esses dados como props para as telas filhas.
  • Mapa de telas Um objeto JavaScript mapeia cada seção da URL para seu componente de tela. Ex: "alunos" → TelaAlunos, "dashboard" → TelaDashboardAluno|Professor|etc
  • mostrarToast(msg, tipo) Cria notificações flutuantes (sucesso/erro/aviso). Auto-remove após 3,5 segundos. Máximo 3 toasts simultâneos.
  • alternarConclusaoConteudo(id) Marca/desmarca um conteúdo como concluído, salva no localStorage e atualiza o estado global.

Pasta src/componentes/
Blocos reutilizáveis usados em múltiplas telas

Os componentes são peças de UI isoladas que recebem dados via props e não dependem de nenhuma tela específica. Podem ser reusados em qualquer lugar.

ComponenteProps principaisO que faz

Modal.jsx titulo, onFechar, children Dialog acessível com foco preso dentro (useFocusTrap). Fecha com ESC, clique no overlay ou botão X. Atributos ARIA: role="dialog", aria-modal, aria-labelledby.
Toast.jsx toasts[], onFechar(id) Notificações flutuantes no canto da tela. Tipos: sucesso (verde), erro (vermelho), aviso (amarelo), info (azul). Auto-dismiss após 3,5s. Máximo 3 simultâneos.
Insignia.jsx texto, variante? Badge colorido. Mapeamento automático de texto para cor: "Aprovada"→verde, "Pendente"→amarelo, "Rejeitada"→vermelho, "Ativo"→verde, "Inativo"→cinza.
CartaoEstatistica.jsx icone, valor, rotulo, corBorda? Card de KPI. Layout: ícone à esquerda, valor grande + rótulo à direita. Borda superior com cor customizável. Usado nos dashboards.
BarraProgresso.jsx percentual, mostrarTexto? Barra de progresso visual (0-100%). Acessível: role="progressbar", aria-valuenow, aria-valuemin, aria-valuemax. Clamp automático. Cor roxa degradando para roxo claro.
SelectSimples.jsx value, opcoes, onChange, placeholder, erro Dropdown customizado (substitui o select nativo). Posicionamento fixed para não ser cortado por overflow. Navegável por teclado. Aceita array de strings ou objetos {valor, rotulo}.
SelectUsuario.jsx value, opcoes (usuários), onChange Versão do SelectSimples especializada para selecionar usuários. Exibe iniciais do nome como avatar. Inclui opção "Nenhum" (null).
NavGrupo.jsx usuario, secaoAtual Barra de abas horizontal abaixo da topbar. Aparece quando a seção tem subgrupos (ex: Gestão tem Alunos, Professores, etc). Função temNavGrupo() detecta quando renderizar.
ModalEdicaoUsuario.jsx usuario, onSalvar, onFechar Modal completo para editar dados de qualquer usuário. Campos: nome, email, telefone, cidade, estado, status. Validação básica. Usado em TelaUsuarios, TelaAlunos, TelaProfessores.
BarraLateral.jsx usuario, secaoAtual, aberta, onFechar, onLogout Sidebar de navegação. Grupos accordion (Gestão, Acadêmico, Aprendizado) com ícones. Recolhível com hover peek. Badges de notificação. Botão sair com modal de confirmação. Salva estado em localStorage.
BarraTopo.jsx usuario, secaoAtual, onLogout, onAbrirSidebar Header fixo. Breadcrumb (CodeRyse Academy › Seção). Para Aluno: atalhos Meus Cursos e Certificados com sublinhado ativo. Popup de perfil: Meu Perfil, Configurações, Sair. Botão hamburger para mobile.
BarraNavMobile.jsx usuario, secaoAtual Barra de navegação inferior em telas pequenas. Exibe as seções principais do perfil com ícones e labels. Visível apenas em mobile (max-width: 768px).

Sistema de design CSS — variáveis, reset, componentes e telas

Todos os estilos são CSS puro, sem bibliotecas como Tailwind ou Bootstrap. Organizado em camadas: variáveis globais → reset → componentes → layout → telas específicas.

ArquivoO que defineClasses principais
variaveis.css Tokens de design (CSS Custom Properties em :root) Cores: --cor-marca (#7b2ff7), --cor-fundo (#191b21), --cor-texto-forte
Espaçamento: --espaco-xs/sm/md/lg/xl/2xl
Tipografia: --texto-xs/sm/md/lg, --fonte-principal

Hooks customizados do React
📄 useFocusTrap.js
Hook de acessibilidade WCAG 2.1 que prende o foco do teclado dentro de um modal aberto.
  • O que faz Quando um Modal abre, captura todos os elementos focáveis dentro dele (buttons, inputs, links, selects, tabindex). Tab/Shift+Tab circula apenas entre esses elementos, nunca sai do modal.
  • Restauração Salva qual elemento estava focado antes do modal abrir. Ao fechar, devolve o foco para ele — importante para usuários de leitor de tela.
  • Por que é necessário Requisito WCAG 2.1 AA (critério 2.1.2 No Keyboard Trap). Sem o trap, ao pressionar Tab dentro de um modal o foco pode escapar para elementos atrás do overlay.

Primeiro arquivo JavaScript executado pelo navegador. Três responsabilidades:

Aplicacao.jsx — Roteador e Autenticação

// Estado global: quem está logado
const [usuarioLogado, setUsuarioLogado] = useState(() => {
  const chave = localStorage.getItem("coderyse-perfil");
  return chave ? (usuariosPorPerfil[chave] ?? null) : null;
});

// Login: salva no localStorage, navega para /painel
function fazerLogin(chave) {
  localStorage.setItem("coderyse-perfil", chave);
  setUsuarioLogado(usuariosPorPerfil[chave]);
  navigate(ROTAS.PAINEL);
}

// Logout: remove do localStorage, volta para /
function fazerLogout() {
  localStorage.removeItem("coderyse-perfil");
  setUsuarioLogado(null);
  navigate(ROTAS.INICIO, { replace: true });
}
RotaProtegida — componente simples: se usuario é null, redireciona para / com Navigate replace. Caso contrário, renderiza os filhos. Isso impede acesso ao painel sem login.

Fluxo de Login

1
Usuário acessa / (TelaInicio) e clica em "Entrar"
↓
2

3

↓
4
Navega para /painel, LayoutWorkspace recebe o objeto usuariosPorPerfil["aluno"] como prop
↓
5
Dashboard do Aluno é renderizado com dados reais do localStorage

Fluxo de Progresso do Aluno

1
Aluno acessa TelaConteudos — vê lista de conteúdos do módulo
↓
2
Clica no CheckCircular — dispara onAlternarConclusao(conteudoId)
↓
3
LayoutWorkspace atualiza o Set conteudosConcluidos e chama db.progresso.salvarConcluidos(set)
↓
4
localStorage cdr_concluidos é atualizado
↓
5
TelaProgresso e TelaDashboardAluno releem o Set e recalculam percentuais automaticamente

Fluxo de Matrícula

1
Aluno acessa TelaCatalogo — clica em "Solicitar matrícula" em um curso
↓
2
Nova matrícula é criada com status: "Pendente" no db.matriculas
↓
3
Admin acessa TelaMatriculas — aba "Pendentes" — aprova individualmente ou em massa
↓
4
Status muda para "Aprovada" — aluno agora vê o curso em TelaProgresso e TelaConteudos

Fluxo de Certificado

1
Aluno conclui todos os conteúdos de todos os módulos do curso
↓
2
TelaProgresso exibe botão "Iniciar avaliação final"
↓
3
Aluno realiza a avaliação em TelaAvaliacoes — nota calculada
↓
4
Se nota ≥ 60%: onAvaliacaoAprovada(cursoId, {nota, notaMaxima, porcentagem}) salva em cdr_avaliacao_aprovada
↓
5
TelaCertificados exibe o certificado com botão "Imprimir" → abre janela de impressão com layout do certificado
